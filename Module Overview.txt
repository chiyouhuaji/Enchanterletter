========================================
Enchanter Letter
Minecraft 1.21.1 / 1.20.1 Mod Introduction
Supported loaders: NeoForge / Forge / Fabric (multi‑version sync)
========================================

I. Mod Overview
----------------------------------------
This mod adds a series of "Enchanter Letters" (Enchanter Letter) and "Letter Binders" (Letter Binder).
Letters are beneficial items carried in the inventory or curios slots: when the holder deals damage of a specified type, the letter provides a damage boost according to its level (by default it works on UsefulMagic's usefulmagic:magic damage, and any damage type can be added via config files or commands). Letters can also be bound to a player, enchanted with "Magic Conversion" to change the damage type, and are compatible with other curios mods (Curios / Accessories).

Letters are non‑stackable items (each occupies one slot) and can be stored together in a Letter Binder for unified management.


II. Letter Types and Progression
----------------------------------------
Each letter has a "Level (Lv)"; higher levels grant higher damage boosts. Levels increase through the corresponding actions:

Experience Letter (experience): gain 1,000 experience points to level up; +10% damage per level.  
Kill Letter (kill): kill 50 mobs to level up; +10% per level.  
Fishing Letter (fishing): catch 100 fish to level up; +10% per level.  
Travel Letter (travel): walk 5,000 blocks / fly 20,000 blocks to level up; +10% per level.  
Treasure Letter (treasure): open 20 natural chests to level up; +10% per level.  
Time Letter (time): based on server world time (every 3,600 seconds to level up, +10% per level), independent of player playtime.  
Tenacity Letter (tenacity): endure 10,000 damage to level up; +10% per level.  
Hero Letter (hero): win 1 raid to level up; +10% per level for low levels, +20% per level starting from level 4; the item’s progress description is split into "Low‑Tier Raids / High‑Tier Raids" (the sum equals total raid victories; low‑tier counts victories before reaching the high‑tier threshold, high‑tier counts victories after).  
Stage Letters (stage_1 ~ stage_10): fixed‑multiplier letters, sequentially 100%, 200%, 300% … 1000%; multipliers can be changed in the config.  
Custom Letter (custom): level is always 0 and does not participate in growth/progress; damage multiplier, armor value, armor toughness, and resistance boost all default to 0 and can be manually configured.

(The above numbers are the default values in the config files and are fully adjustable; custom letters are excluded. The default values for the eight growth‑type letters only serve as initial values when a new letter is created (creative inventory / /give); each letter’s actual numbers are stored individually in that letter’s own data.)

[Damage Boost Application Rules]
A letter placed in the inventory (or curios slot / binder) counts as being carried; it does not need to be held.  
Boost targets: damage types listed in the config option `default_bonus_damage_types` (default `usefulmagic:magic`); any registered damage type can be added.  
Effective multiplier = Letter Level × Boost per Level (the current actual multiplier is shown in the item tooltip and HUD).  
Unenchanted letters apply directly to the default damage type; letters enchanted with "Magic Conversion" calculate using the converted damage type.


III. Stacking Rules (stacking_rules)
----------------------------------------
allow_multiple_letters (default false):
- false — regardless of how many letters are carried, only the one with the highest multiplier takes effect;
- true — the multipliers of all letters are summed and take effect.

allow_same_letters (default false):
- If two letters are identical in every aspect except conversion state (same item, same multiplier, same damage type, same enchantment state), false means only one takes effect, true means each takes effect.


IV. Binding System
----------------------------------------
While holding a letter (or an empty Letter Binder), sneak + long‑press right‑click for about 2 seconds to bind/unbind: after binding, the item tooltip shows “Bound: <player name>”.  
When the bound player holds the letter it works normally; if someone else picks up / holds your bound letter, the letter will not take effect and will be automatically “ejected” as a dropped item (checked every second; inventory, Curios / Accessories slots, and binder contents are all checked).


V. Dropped Item Protection
----------------------------------------
All letters and binders, when dropped, are protected:
- Immune to explosions, cacti, and all other damage;
- No gravity, velocity constantly zero, remain stationary (not moved by water flow);
- Cannot be sucked into hoppers / hopper minecarts.


VI. Letter Binder (Letter Binder)
----------------------------------------
Usage is identical to the vanilla shulker box (right‑click to store/retrieve, inventory interaction, hover to view contents);
Letters are non‑stackable, each occupies one slot; the vanilla binder can hold up to 64 letters;
Hovering correctly shows letter count / capacity progress;
When empty, sneak + long‑press right‑click to bind/unbind the binder itself;
When not empty, sneak + right‑click to dump all contents at once;
Letters inside the binder count as “carried” and participate normally in damage boosts and ejection checks.


VII. Magic Conversion Enchantment
----------------------------------------
After enchanting a letter with “Magic Conversion” (`magic_conversion`):
- The letter’s boost is no longer bound to the default damage type but is calculated using the specified damage type;
- Use `/letterdamage <damage type>` to set the conversion damage type;
- In creative mode, right‑clicking a enchanted book with this enchantment opens a client‑side settings GUI where you can directly input the damage type ID;
- Conversion calculations are grouped by damage type: letters of the same type have their multipliers combined and are resolved together, while different conversion types do not interfere with each other.


VIII. Curios Slot Compatibility
----------------------------------------
NeoForge / Forge: Curios slots (including slots added by other Curios‑compatible mods); this mod allows letters / binders in those slots.  
Fabric: Accessories and Curios (Fabric).  
All are optional compatibility: if the corresponding mod is not installed, there is no impact on usage; letters placed in curios slots work the same and participate in binding/ejection checks.


IX. HUD Display
----------------------------------------
The top‑left corner of the screen continuously shows the currently active letters list (item name, level, actual multiplier; enchanted conversion letters also show the conversion damage type). Gray text indicates letters that are currently not active (overridden by a higher multiplier), white text indicates active letters.  
Default toggle key is N (can be changed in the client config).

XI. Commands (all require permission level ≥ 2, i.e., usable by levels 2/3/4)
----------------------------------------
`/lettermulti [true|false]` – toggle “multiple letters active simultaneously” (no argument flips current value).

`/lettersame [true|false]` – toggle “identical letters each take effect” (no argument flips).

`/letterset <type> <param> <value>` – modify growth values; `<type>` supports (tab‑complete):
`experience|kill|fishing|travel|treasure|time|tenacity|hero|custom|stage_1~stage_10`
`<param>` supports (tab‑complete):
`time|time2|damage|damage2|armor|armor2|toughness|toughness2|resistance|resistance2`

The per‑level parameters for the eight growth‑type letters (time/time2, damage/damage2, armor/armor2, toughness/toughness2, resistance/resistance2) are stored in each letter’s own item data: the command behaves three ways depending on the main‑hand situation—if the main hand is empty (or the executor is not a player) the parameters are written to the config file and saved (legacy behavior); if the main hand holds the corresponding letter type, the parameters are written directly to that letter’s data, causing the letter’s level, multiplier, armor, toughness, and resistance boost to be instantly recalculated and reflected in the tooltip and HUD; if the main hand holds any other item, the command does nothing. Config defaults only serve as initial values for newly created letters and are no longer involved in later calculations.

Examples:
- `/letterset time damage 0.05`   (time letter damage boost per level → 5%)
- `/letterset stage_4 damage 2.5`  (stage 4 multiplier → 250%)
- `/letterset stage_4 armor 5.5`   (stage 4 armor value → 5.5)
- `/letterset stage_2 resistance 0.3` (stage 2 resistance boost → 30%)
- `/letterset custom damage 1.5`  (custom letter damage multiplier → 150%)
- `/letterset custom armor 4.0`   (custom letter armor value → 4.0)
- `/letterset custom resistance 0.2` (custom letter resistance boost → 20%)

Stage letters have fixed values per stage (configured individually, e.g., `stage_N` directly specifies the multiplier); armor/toughness are direct numbers, resistance is a reduction ratio; modifications to stage letters are still written back to the config. Custom letters do not grow by count/level; their values are written directly to the item data and not to the config; they must be held when executing the command.

`/lettertype add|delete <damage type>` – add or remove a damage type from `default_bonus_damage_types`. Tab‑completion for `add` lists all registered damage types not yet added; for `delete` it lists currently configured types. Example: `/lettertype add minecraft:magic`

`/letterentity add|delete <entity type>` – add or remove an entity type from `magic_conversion.blacklist_entity_names` (blacklisted entities do not undergo magic conversion). Tab‑completion for `add` lists all registered entity types not yet added; for `delete` it lists the current blacklist. Example: `/letterentity add minecraft:warden`

`/letterdamage <damage type>` – set the conversion damage type of the held “Magic Conversion” enchanted letter.

`/letterback [player]` – search all loaded dimensions for dropped items and teleport bound letters/binders belonging to the command executor (if no argument) or the specified online player (tab‑complete) to that player’s location, with zero velocity for immediate pickup.  
Examples:  
`/letterback`     (retrieve your own letters)  
`/letterback Steve` (retrieve Steve’s letters)

`/lettercolor <red> <green> <blue>` – set the “glowing” color of the held letter/binder to the specified RGB values (0‑255 each; e.g., `/lettercolor 255 0 0` = red; `0 0 0` = white). When multiple glowing‑enchanted items are held, the displayed color is the average of all.

`/letterenchanted` – query the enchanted‑book addition logic switch and the three enchantment probabilities.  
`/letterenchanted true|false` – enable/disable enchanted‑book addition logic.  
`/letterenchanted glowing <0.0~1.0>` – set glowing enchantment appearance chance on enchanted books.  
`/letterenchanted binding <0.0~1.0>` – set magic binding enchantment appearance chance.  
`/letterenchanted conversion <0.0~1.0>` – set magic conversion enchantment appearance chance.  
(Probabilities are independent; a single enchanted book may contain multiple.)

`/letterclean` – query cleanup status (on/off, interval, list).  
`/letterclean on|off` – toggle timed cleanup.  
`/letterclean time <seconds>` – set cleanup interval (minimum 1).  
`/letterclean add <UUID>` – add a UUID to the cleanup list.  
`/letterclean delete <UUID>` – remove a UUID from the cleanup list.  
`/letterclean add allbinding` – enable “clean all bound letters/binders drops”.  
`/letterclean delete allbinding` – disable that option.  
`/letterclean add allnormal` – enable “clean all unbound letters/binders drops”.  
`/letterclean delete allnormal` – disable that option.  
`/letterclean all` – clean all letters/binders drops.  
`/letterclean all confirm` – confirm and execute.  
`/letterclean uuid <UUID>` – clean drops bound to the specified UUID.  
`/letterclean uuid <UUID> confirm` – confirm and execute.

`/letterdelay` – query current respawn return delay (ticks).  
`/letterdelay <tick>` – set respawn return delay (ticks, 0‑6000, default 20): after player respawn wait this duration before executing ① forced re‑equip of bound items and ② removal of vanished cursed items. Config key `letter_respawn.restore_delay_ticks`.

`/letterstorage nbt [<uuid|player>]` – without a target parameter: output all NBT data of the currently captured entity (see section XIII for no‑parameter form); with a target parameter: resolve the target (UUID or online player name, tab‑complete) and lock it as the current captured entity, then output all its NBT data – the target must exist and be loaded, otherwise an error is thrown.

`/lettereffect add <slot> <effect> <seconds> <amplifier> <hideParticles> <loopMode> <looptime> [<looptime2> ...]`  
`/lettereffect delete <slot>`  
`/lettereffect ls` – manage potion effect entries for the “main‑hand magic letter” (entries stored in the letter’s own data, default empty, no config needed; must be executed while holding a magic letter in the main hand, permission 2/3/4):  
- `add` writes/overwrites an effect entry at the specified slot (≥ 1); if the slot already has an effect it is overwritten (slot number retained), otherwise a new entry is created; parameter meanings and two trigger modes (daytime / gametime) are detailed in section XIV.  
- `delete` removes the effect entry at the given slot; the slot number becomes reusable.  
- `ls` lists all current effect entries (`#slot effect sec level hideParticles mode times`).

Note: Apart from `/letterset`, all commands that modify config values take effect immediately and write back to the config file; `/letterset` still writes to the config when used on the eight growth‑type letters while the main hand is empty (or the executor is not a player), but writes to the item data when the corresponding letter is held; it does nothing when holding other items. Custom letters require holding the corresponding letter to write to item data; stage_1 ~ stage_10 still write back to the config; `/letterset`, `/lettertype`, and `/letterentity` all support tab‑completion.


XII. Defensive Attributes (Armor / Armor Toughness / Resistance Boost)
----------------------------------------
All letters (including stage letters) provide three additional defensive attributes that take effect while carried (inventory, curios slot, or binder), growing synchronously with the existing damage‑boost logic:

1. Armor (`armor`) – directly adds a flat value (not a multiplier) that is permanently added to the carrier’s armor attribute, participating in armor damage reduction (visible on the player’s armor bar; also visible with mods like Overloaded Armor Bar). No vanilla cap needs to be considered; players can install mods that lift the cap if desired. Default per‑level increase: non‑stage letters +0.1 points; stage letters have individually configurable values (default retains the original fixed +2 per level: stage_1 = 2, stage_2 = 4 … stage_10 = 20, but can be changed per stage, decoupled from stage number/level).

2. Armor Toughness (`toughness`) – directly adds a flat value (not a multiplier) that is permanently added to the carrier’s toughness attribute (also shown in the player’s armor info). Default per‑level increase: non‑stage letters +0.01 points; stage letters have individually configurable values (default retains the original fixed +1 per level: stage_1 = 1, stage_2 = 2 … stage_10 = 10, but can be changed per stage).

3. Resistance Boost (`resistance`) – a reduction ratio (multiplier), applied similarly to the vanilla Resistance potion: damage is reduced by the ratio before armor calculation. All letters default to 0 (no effect); users may configure values themselves. Final reduction = min(level × increase per level, server‑allowed maximum); server default maximum is 0.8 (80%) and can be changed with `/letterresistance limit`.
